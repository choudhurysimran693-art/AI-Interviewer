# Verification and remaining dependencies

- First and last names are required; middle name is optional.
- New interviews sample resume and role templates with randomized wording and resume entries. Existing interview questions stay fixed on reload. Generated questions receive a variation seed.
- Start and Stop recording control saved microphone audio. Supported browser SpeechRecognition supplies provisional live captions; this may use the browser vendor's speech service. Final audio transcription and candidate approval precede evaluation. Unsupported browsers explicitly report unavailable live captions.
- HR screening requires fullscreen, a visible focused page, successful detector inference, and evidence storage. Clipboard copy/cut/paste and drag/drop are blocked while in HR screening. These are browser controls, not an OS lockdown: a managed exam client is required to prevent switching applications altogether.
- Face monitoring now runs in a classic worker because the installed MediaPipe WASM loader uses importScripts. Failures never update inference timestamps or signal successful monitoring. Device inference errors and model download progress are visible.
- Facial emotion/stress inference was removed. Face-count observations do not infer mental states.
- Scoring is available without an API key through the deterministic local rubric and is labeled `source: local_rubric`; when GEMINI_API_KEY is configured, validated provider scoring is used. Camera observations and emotion labels are never evaluator inputs.
- The face worker uses the pinned local MediaPipe model. The device worker uses the pinned local Grounding DINO model and fails closed when it cannot produce finite inference output; there is no rectangular-object or simulated detection fallback. Automated checks cover account ownership, assignments, locks, termination/blocking, evidence access, five-answer scoring, consent, expiry, transcript approval, and monitoring requirements. They do not prove detector accuracy, real microphone transcription, or provider availability.
- The current browser smoke test confirmed real face counts but showed that one tested graphics adapter produced invalid half-precision Grounding DINO output. The worker now tries full-precision WebGPU and rejects invalid output; CPU fallback is available but may exceed the one-second pilot target. Run the required phone/tablet/negative clip validation on each supported Chrome/Edge computer before enabling production HR screening.
- Accounts use secure HTTP-only sessions with CSRF protection. HR accounts are provisioned by an administrator. Password recovery is an administrator-issued, one-use reset link; email delivery is intentionally not configured. Run `python -m backend.app.manage create-admin` once for the first administrator.
